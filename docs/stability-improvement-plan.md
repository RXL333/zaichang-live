# 在场会议稳定性改进计划

## 范围与顺序

第一阶段依据用户提供的改进方案实施 S1–S6：先处理服务唤醒和错误提示，再统一弹窗交互与键盘操作，随后设置自动化测试门禁，整理验证记录并核对会议后端安全。

- 保持现有 Vue、Spring Boot、WebSocket、LiveKit Cloud、Neon 和部署方式；保留账号和现有会议数据。
- 会议协议、鉴权方式和数据库结构不在本阶段修改。安全核对中，只直接补充适合现有部署的限流或输入限制，并用测试覆盖；其余记录位置与限制。
- 后端休眠时低频重试健康检查；仅在状态恢复后重新加载用户和会议数据，不持续轮询。未实测的唤醒耗时明确记为待实测。
- 通用弹窗支持焦点管理、键盘操作和危险操作确认；设备错误以用户能采取的行动说明，取消屏幕选择不显示错误。
- CI 分别运行前后端测试，发布任务只使用通过测试的 main 提交；部署和回退保持可追踪。

## 验证

分别运行前端安装、测试和生产构建，以及后端 Maven 测试；覆盖健康检查重试、设备错误、弹窗焦点、危险操作和所做的后端加固。验证结果只记录实际执行的命令；真实设备、休眠唤醒、多人音视频及其他未执行场景单独列出。

完成第一阶段后汇报，并按原方案等待下一阶段指示。
