# 主持人控制（F4）

第二阶段 F4 增加全员静音、会议锁定与主持人转让。新建会议由创建者主持，会中可把主持人角色交给其他成员。验证范围见[验证记录](verification.md)。

## 行为和权限

1. **全员静音**：当前主持人向其他在线成员发起静音。每位成员仍可自行重新打开麦克风。媒体服务若只完成部分操作，向主持人明确显示部分失败，不报告全部成功。
2. **锁定会议**：锁定后，新会话不能加入；已经取得该会议授权的会话仍可重连或重新进入，直到退出登录或被移除。该规则兼顾刷新和网络中断，但也意味着已离会且会话仍有效的人可以重新进入。解锁后恢复正常加入。
3. **转让主持人**：主持人可将角色交给当前在线成员。会议创建者仍是所有者，可在首页编辑或删除自己创建的会议；会中的静音、移出、锁定、转让和结束会议由当前主持人控制。
4. **主持人连接中断**：保留约 15 秒恢复时间；若主持人仍未连接且有其他在线成员，再转给最早进入的在线成员。如果当时没有其他成员，保留原主持人，不自动把权限交给后来加入的人。

## 数据和事件

- `meetings` 使用 `ADD COLUMN IF NOT EXISTS` 增加 `locked BOOLEAN NOT NULL DEFAULT FALSE` 和可空的 `host_user_id VARCHAR(40)`。旧记录默认未锁定，空主持人按 `owner_id` 处理。
- WebSocket 新增 `MUTE_ALL`、`SET_MEETING_LOCK`（带布尔值）和 `TRANSFER_HOST`（带目标用户 ID）。服务端逐项验证会话、会议授权和当前主持人身份。
- `JOINED` 回传当前主持人及锁定状态，`MEETING_LOCK_CHANGED` 和 `HOST_CHANGED` 广播变更。全员静音沿用现有 `MUTED` 提示，发起操作的连接收到 `MUTE_ALL_RESULT`，包含已静音和未确认的人数。
- 会议详情返回 `locked` 和当前会话的 `canRejoinLockedMeeting`，会中状态返回 `hostUserId`。加入与锁定切换使用同一会议锁，避免并发时新成员绕过锁定。
- 成员是否在线以会议 WebSocket 活跃连接为准，同一账号的多个连接按一人处理。自动转让前再次检查当前主持人和候选人的有效会话。

## 兼容性、验证和回滚

升级后的页面根据会中状态的 `hostUserId` 显示新入口，可先于服务端发布。旧客户端在转让后可能仍显示原主持人，刷新页面可同步。服务端按实际角色校验管理操作，主持人转让只改变会中管理权。

测试覆盖非主持人指令被拒绝、不同会议隔离、锁定与并发入会、已授权会话重连、全员静音部分失败、转让和短暂断线恢复。部署前验证数据库升级和重复启动，并在生产环境保存数据库备份、代码和镜像。

回滚时恢复原镜像和代码，保留新增列。回滚版本由原会议所有者负责管理，会议锁定功能会暂停。
