# 主持人控制提案（待确认）

本提案对应第二阶段 F4。当前创建者同时是会议所有者和主持人；系统已有单人静音、移出和结束会议。以下内容涉及会议事件、权限及数据库字段，确认前不实施。

## 行为和权限

1. **全员静音**：当前主持人向其他在线成员发起静音。每位成员仍可自行重新打开麦克风。媒体服务若只完成部分操作，向主持人明确显示部分失败，不报告全部成功。
2. **锁定会议**：锁定后，新会话不能加入；已经取得该会议授权的会话仍可重连或重新进入，直到退出登录或被移除。该规则兼顾刷新和网络中断，但也意味着已离会且会话仍有效的人可以重新进入。解锁后恢复正常加入。
3. **转让主持人**：主持人可将角色交给当前在线成员。会议创建者仍是所有者，可在首页编辑或删除自己创建的会议；会中的静音、移出、锁定、转让和结束会议由当前主持人控制。
4. **主持人连接中断**：保留约 15 秒恢复时间；若主持人仍未连接且有其他在线成员，再转给最早进入的在线成员。如果当时没有其他成员，保留原主持人，不自动把权限交给后来加入的人。

## 数据和事件

- 在 `meetings` 中增加 `locked BOOLEAN NOT NULL DEFAULT FALSE` 和可空的 `host_user_id VARCHAR(40)`；旧记录的空主持人按 `owner_id` 处理，或在迁移中以 `WHERE host_user_id IS NULL` 补齐。字段添加使用 `ADD COLUMN IF NOT EXISTS`，先在数据库副本验证；不删除表或重建表。
- WebSocket 新增主持人指令：`MUTE_ALL`、`SET_MEETING_LOCK`（带布尔值）、`TRANSFER_HOST`（带目标用户 ID）。服务端逐项验证会话、会议授权和当前主持人身份。
- 新增广播：`MEETING_LOCK_CHANGED` 和 `HOST_CHANGED`；全员静音沿用现有 `MUTED` 提示，主持人收到实际成功／失败结果。
- 会议详情增加 `locked` 和当前会话是否有重新进入资格的信息；旧字段继续保留。加入与锁定切换使用同一会议锁，避免并发时新成员绕过锁定。
- 成员是否在线以会议 WebSocket 活跃连接为准；同一账号的多个连接按一人处理。自动转让前再次检查主持人是否已恢复，避免短暂断线造成错误转让。

## 兼容性、验证和回滚

旧客户端会忽略新增事件，但转让后可能仍显示旧主持人；服务端仍会拒绝越权操作，应提示刷新页面。会中媒体权限不因主持人转让而扩大。

实现时覆盖：非主持人指令被拒绝、不同会议隔离、锁定与并发入会、已授权会话重连、全员静音部分失败、转让和短暂断线恢复。先在本地及数据库副本验证，再备份生产数据并部署。

回滚时恢复原镜像和代码，新增列保留，不执行 `DROP`。旧版本不会识别锁定或新主持人，因此回滚前需通知参会者并明确锁定保护将暂停；回滚后由原会议所有者负责管理。
